Query katalog dan KDS menggunakan index (type: ref, bukan full scan), namun dengan volume data seeder saat ini (1–2 baris per tenant), optimizer MySQL memilih index unique (tenant_id, id) alih-alih index composite yang dirancang, karena kedua index memberi estimasi baris yang sama kecil. Perilaku ini wajar pada skala data kecil dan perlu diverifikasi ulang dengan volume data produksi-like untuk memastikan index composite benar-benar terpakai saat data membesar.
